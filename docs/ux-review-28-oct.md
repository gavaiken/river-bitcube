## Batch A: controls that can mislead or misfire at the show (do first after Batch 0)

1. **Looks tab shows the old state for up to 60 s after Apply / Pin; Back is greyed meanwhile.** `tools/mission/probe.ps1` `-Action looks` reads `status.json` right after writing `control.json` (TD reads it once a second); the next reading is the full check (60 s); `looks-page.js` `onSent` drops the draft. Fix: in `looks-words.js` `pageView`, when `v.asked` (control.json) differs from `v.now` (status), show the asked playlist/mode with the line "sent, bitcube hasn't shown it yet"; base Back's greying on `asked.mode ?? now.mode`; have probe.ps1 wait up to 2 s for `status.json` to reflect the `at` it wrote (same pattern the remembered controls could use). Test in `looks.test.mjs` with a fixture where asked ≠ now.
2. **Apply's promise is wrong and Help contradicts it.** `looks-page.js:24` "bitcube plays it from its first look"; `help.html` says "from the look showing now". `td/looks/mixer.py` `Looks.set`: keeps its place if the look showing is in the new list, else fades to entry 1. Fix: one sentence in `looks-words.js` (new export `applyWords`) used by the page's control `before:` and quoted in Help: "Keeps the look showing if it is in the new list, otherwise fades to the first one; then round and round." Mirror `set()` in `lib/fixtures.mjs` (today the fixture jumps to entry 1).
3. **"Back to the playlist" can skip a look at once.** `mixer.py` `set()` manual→auto resets `loops_done` but not `came_on`: a look pinned 30 min with a 10-minute entry advances immediately. Fix: `came_on = self.now` wherever `position`/`target` is reassigned in `set()`; test in `tools/tests/test_looks.py`.
4. **Status's Looks card says "Playing … 2 of 3 · minute 5 of 10" while pinned.** `status.js` `lkPlaying` renders whenever `n.playlist` exists. Fix: only when `n.mode === 'auto'`; in manual: "Pinned: <look>". (Moves to `status-words.js`, see C1.)
5. **The Screens sliders overwrite intensity silently.** `remembered.js` Apply sends all three; the 5 % step rounds bitcube's 82 % to 80 %. Fix: send only sliders moved (`S.scrTouched`), label shows bitcube's exact value; and `remembered-words.js` default intensity 0.8 so the slider can show it (or step 1 %). TD: `show.py` `screen_intensity or 0.82` turns 0 into 82 % while reporting 0: use `is None`. Hint "ribbons and video alike" is false on the GPU path (the river uses `water.s['intensity']`): say "the ribbons" (or scale the GPU river by it in `params_image`: one line, better).
6. **`PLAYLIST_ONLY` is false: the two-looks file obeys a leftover playlist.** All looks files run the same mixer. Fix (TD): in `mixer.frame`, ignore `control.json` `playlist` unless `_project_name() == 'river-all-looks.toe'` and don't report `playlist` in status for the others; (mission) keep the gate but word it from status (`playlist` present) not the file name. Test both.
7. **The Looks tab headline "No look is showing" when another file runs** (`looks-page.js:59`) reads as "dark". Fix: "The playlist file isn't running: <title> is showing" (words in `looks-words.js`).
8. **Pin on a playlist row can be a silent no-op** (`looks-page.js:86`: the row button stays enabled while the section's Pin is greyed). Fix: grey the row's button with the same reason, aria-label "Pin <look>"; after pressing, scroll to the section's control.
