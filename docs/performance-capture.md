# Full-playlist performance capture

`tools/remembered/profile_capture.py`, executed through `tools/td.ps1`, times the existing all-looks callbacks for 1,500 seconds (25 minutes). The usual playlist is four 300-second remembered loops plus an approximately 84-second fill. Flood shortcuts can make it shorter. No restart, rebuild, control write, video switch, GPU image readback or project save is used. Keep the current approved runtime video trial intact; **do not save that trial into the show**.

Start: `tools\td.ps1 -File tools\remembered\profile_capture.py`. The tool prints the timestamped `River\profiles\cycle-...` directory and process IDs. It refuses a second active capture or a different show. Status/stop: execute the same file with `CAPTURE_ACTION='status'` or `'stop'` in its execution globals. `CAPTURE_SECONDS` overrides the duration for a short diagnostic.

The wrappers time every callback, selected nested Python sections, TD-reported CPU/GPU cook times, and actual Art-Net send intervals. They preserve arguments/results/exceptions and restore themselves at the duration limit. The original code is called even on the expiry frame. Queueing and a background writer keep disk I/O off the frame thread. No unpicklable objects enter component storage. A separate windowless Python process uses native Windows read-only counters at 1 Hz for CPU, memory and current show phase; it does not install packages or run repeated WMI queries. Files are local under River/profiles, outside the public repo. Process names/command lines and camera credentials are not collected.

`events.csv`: raw frame intervals, callback/section timings, clip, look and loop; rope-send events. `system.csv`: CPU/memory/phase. `capture.json` becomes complete after callbacks are restored and data flushed; `system-complete.json` marks the external sampler’s completion. `metadata.json` records PID/start/duration. On a TD crash/restart, the wrapper vanishes with the process and the flushed partial trace remains; do not label it a full capture. No automatic restarts or optimization changes.

Analyze with `python tools/remembered/profile_report.py <folder>`. Report percentiles and episodes, compare slow windows with phase/clip transitions, and inspect field_screens (periodic CPU ribbon rendering), water_feed (mask), rope_step, GPU cook times and Art-Net gaps. Section timings are nested/inclusive, so do not add them. GPU values may reflect a prior cook or unavailable queries; raw callback intervals do not prove physical presentation timing. Check overhead, dropped diagnostic rows, coverage of every playlist entry, and input changes before attributing a cause.
