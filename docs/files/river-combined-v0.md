# Combined v0

Will's first visualization: the live river in Gavin's summer colours, with Dave's animation added over it. [All show files](../show-files.html)

## What it does
- **Reads:** live river video through the established camera relay. If no frame arrives for 10 seconds, uses `River/recordings/river/seasons/river-normal.mp4`, and returns to live video when frames resume. The live camera clock and label are cropped like the recorded library. Gallery video is available as `viz/gallery_in`; it does not steer the Combined base. The optional Gavin-style screen branch retains his existing presence-driven seasonal engine.
- **Base:** holds summer at intensity 0.85, using Gavin's summer palette, natural tint, downward torrent streaks and sun glints. Live video runs at camera speed; this version does not synthesize faster playback of the live river.
- **Overlay:** Dave's canvas from the existing local Modal mirror (`http://127.0.0.1:8770/canvas.html?w=640&h=360`). His scene drives his animation; it does not change the summer base in v0. Bright canvas forms are added over the river, then clamped. Missing scene or renderer errors leave the base running alone. A network outage keeps the last mirrored scene.
- **Controls:** Status in mission control, while Combined v0 runs: move **Dave's overlay strength**, then press **Apply river settings**. 0% is the summer river alone; 100% adds the full canvas. Starts at 25%; changes persist in `River/combined-v0.json`, independently of other shows. No audio, new recordings or Modal deployment changes. The Combined base is fixed summer; the screen-only Gavin branch retains his existing seasonal rules/presence behavior.
- **River framing:** Status offers **Auto: recognize camera view**, **Original (bypass)**, **Channel**, or **Pool**, each profile with one window or three slowly crossfading windows. Profiles lift shadows and use feathered foreground masks derived from Will’s two night-camera stills. Auto recognizes the two saved views from coarse, exposure-normalized image structure twice a second, waits for a stable match for one second, then uses that view’s three-window profile. Moving, uncertain or stale views use Original; manual profiles remain available. The three crops preserve 16:9, cover successively wider water regions and crossfade every 18 seconds (54-second cycle). Original takes the unchanged input route. Recorded fallback always bypasses framing. Profile and overlay strength share the persisted settings file; changing one preserves the other.
- **Screen fades:** four screens only, independently of the ropes. Choose Current look, Gavin style (live), Gavin style (recorded), Manual blend or Automatic cycle on Status, then Apply river settings. The cycle holds each look for 15/30/60/120 seconds, with 8-second smooth fades between all three looks. Requested starting setting: 30-second holds (114-second full cycle). The cycle runs Current → Gavin live → Recorded → Current. Gavin style (recorded) reuses his original three-speed library blend and seasonal palette/contrast/tint, animated overlays and blur. Its independent year engine reads the same rules/presence as his show. The existing normal decoder plus two added slow/fast movie players loop the three clips; this path works independently of live-camera fallback. The raw clip is no longer a screen look. In Manual blend, Recorded sets its share; the Live blend slider divides the remainder between Current (0%) and Gavin live (100%); changing modes or applying a new blend also fades over 8 seconds. The **Delay between screens** control adds 0–30 seconds between adjacent screen cycles, starting at 10 seconds (offsets 0/10/20/30). Zero synchronizes them; fixed looks and manual mixing ignore the delay. Each screen still holds for 30 seconds and fades for 8 seconds; only its phase changes. Settings persist with framing and overlay.
- **Outputs:** the baseline's 20 ropes and four screens, capped at brightness 0.4 and 600 W per rope box. Uses the baseline's pinned 23 Oct rope and screen maps.
- **Code:** `td/build/build_combined_v0.py`, `td/combined/build_viz.py`, `td/combined/runtime.py`, `td/combined/framing.py`, `td/combined/view_detector.py`, `td/combined/screen_fade.py`, `td/combined/build_screen_seasons.py`, its reference thumbnails and two mask assets.

`inputs -> viz -> outputs`, with `ropes` and `panels` at `/project1`. Keep `viz/river_in`, `viz/gallery_in` and `viz/viz_out`. Change this show's code, rebuild through `tools/td.ps1`, inspect a preview and gallery still, and save only with `tools/td_save.ps1`. Update this page and its registry metadata with every change.

## Reverting the experiment
Choose **Original (bypass)** under River framing and press **Apply river settings**. This restores the pre-framing river path while retaining the overlay strength. It does not require a show restart. The .toe is saved with Original selected; the persisted choice is restored on load.

For a complete file rollback, the pre-framing show and 10% overlay settings are backed up on bitcube at `C:\Users\user\River\checkpoints\combined-v0-before-framing-20261026\`. These are fixed profiles selected from a still-image heuristic, with automatic recognition of two known views, not moving-water segmentation. Daylight, changed lighting, a different camera angle or an imprecise preset can make the masks unsuitable; use Original until retuned. Pool detail remains limited by the camera's exposure.

### Automatic view selection
Auto is a conservative image matcher, not a camera-preset API integration. It compares 32×18 exposure-normalized reference thumbnails with the live image, requiring similarity ≥0.90, a ≥0.10 lead over the other view, and stable matching for one second. A stale detector (>2 seconds), camera fallback or an unrecognized frame uses Original. It does not move the camera. Lighting changes can cause Auto to abstain; use a manual profile or Original then.

## Gavin-style screen branch
Reuses the grade/effects section of `td/build/build_seasons_local.py` verbatim in an independent `viz/gavin_screens` COMP, with his year engine and scoped runtime state. It reads the existing season rules/presence but writes neither and creates no control server. The source is the live river with existing recorded fallback, at camera speed; it does not reintroduce recorded playback-speed changes while live. Rendering at 640×360 supplies sufficient detail for the four physical screens. Original shared builds and shows remain unchanged.

`viz/screen_live_mix` blends the current Combined output with this branch; `viz/screen_mix` then blends that result with `viz/recorded_screen_in`, selecting `viz/gavin_recorded/field_out`. That second seasonal COMP reuses the original library speed-blend expressions and visual build section at 640×360 (normal reuses the baseline decoder; unchanged slow/fast files are not reopened on rebuild), with separate runtime state and no server. The normalized three weights always total one. The recording is already cropped; the recorded look uses Gavin’s seasonal treatment rather than the live framing masks or fixed-summer/Modal treatment. Selecting it never forces the river input or ropes onto recorded fallback. `outputs/screen_field` selects the first mix. Screens 2–4 use their own pairs of mixers (`viz/screen{k}_live_mix`, `screen{k}_mix`) and Select TOPs (`outputs/screen{k}_field`), feeding the same four existing calibrated samplers. Runtime maintains normalized weights and smooth mode changes independently for all four screens. All their calibration, orientation and HDMI routing remain intact. `viz_out`, `outputs/field_out`, the rope sampler and power caps stay on the current Combined output.
